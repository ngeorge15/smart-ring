Does Web Bluetooth work in real Safari via the beacio polyfill? build 1

Requires the free beacio app (App Store) installed, then enabled at Settings → Apps → Safari → Extensions → beacio. This page must be opened in Safari itself, not Bluefy — that's the entire point of the test.

1 · Connect

Use the first button and look for COLMI R02_C302. It can take ~10s to appear — the chooser fills in as devices advertise, so don't give up on an empty list. The second button lists every nearby device, most of them unnamed, and is only a fallback.

2 · Probe

The thing actually being tested here: can the polyfill reach the de5bf728… big-data v2 service at all, and does it survive the ring's real connect time (14–26s observed via Bleak on the Mac, 6.6s–15s+ observed via Bluefy)? A polyfill bridging through a Safari extension process is a longer round-trip than either of those.

3 · Can this be automated?

requestDevice() always needs a tap — that's the spec. But getDevices() doesn't. If it works here, a Shortcut could open the dashboard on a schedule and it would sync with no interaction — same question as the Bluefy probe asked, but now the answer would apply to the SAME page as the dashboard, since Safari has both Web Bluetooth (via the polyfill) and a working service worker.
